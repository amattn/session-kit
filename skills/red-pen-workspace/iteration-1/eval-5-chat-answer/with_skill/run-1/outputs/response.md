Session cookies, stored in Redis. Nothing here favors JWT: the admin panel is a browser UI talking to one service, Redis is already shared across the three replicas (same reason the rate-limiter state lives there), and admin logins are the one place you want instant revocation. A JWT stays valid until it expires unless you add a denylist, at which point you've rebuilt sessions with extra steps. Concretely: HttpOnly, Secure, SameSite=Lax cookie holding a random session id; session record in Redis with a 30-minute idle timeout. One default, no knob, revisit if it bites.

JWT only wins if admin calls come from something that can't hold a cookie (a CLI, another service) or if other services must verify the admin's identity without calling ledgerd. Is either true? If not, I'll record this in NOTES.md.
